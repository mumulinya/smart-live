# SmartLive 项目说明文档

这份文档不是开源接入手册，也不是接口文档，而是面向项目介绍、答辩说明、作品集展示和对外沟通的一份正式项目概览。

如果你是第一次了解这个仓库，建议先读这份文档，再按需跳转到 README、视觉导览和开源接入说明。

## 1. 项目概述

**SmartLive（智评生活）** 是一个面向本地生活服务场景的微服务平台，围绕“用户发现 -> 决策下单 -> 履约评价 -> 社交互动 -> 商家经营 -> 平台治理”构建完整业务闭环。

项目不是单一业务点的 Demo，而是把交易、搜索、社交、审核、即时通讯、支付、积分、热榜、AI/RAG 等能力放进同一套可运行的系统中，强调真实业务链路与工程化落地。

## 2. 建设目标

本项目主要解决三类问题：

- 让用户侧具备“找店、看商品、做决策、下单、评价、互动、聊天、AI 问答”的完整体验。
- 让商家侧具备“商品管理、经营分析、差评回复、内容运营、活动承接”的经营能力。
- 让平台侧具备“审核治理、流量控制、消息异步解耦、缓存加速、搜索与向量检索”的基础设施支撑。

## 3. 项目定位

从系统视角看，SmartLive 同时覆盖三条主线：

- **ToC 用户主线**：首页推荐、搜索找店、店铺详情、商品浏览、下单支付、评价互动、博客发布、AI 问答、IM 消息。
- **ToB 商家主线**：店铺经营、商品上架、订单履约、数据分析、AI 文案与差评回复。
- **平台治理主线**：网关鉴权、内容审核、热榜维护、数据同步、任务调度、搜索索引、向量检索和限流熔断。

## 5. 总体架构

系统采用 Spring Cloud Alibaba 微服务架构，整体可以分为五层：

1. **接入层**
   - 用户端 App、管理端、外部 AI 模型接口等统一从网关进入。
2. **网关与认证层**
   - `smartLive-gateway` 负责统一路由、过滤、鉴权透传与边界防护。
   - `smartLive-auth` 负责登录认证、令牌签发与安全校验。
3. **业务服务层**
   - 由用户、店铺、商品、订单、钱包、积分、博客、互动、搜索、AI、审核、IM 等独立服务组成。
4. **公共能力层**
   - `smartLive-common` 提供 Redis、RabbitMQ、安全、日志、Seata、XXL-JOB 等通用基座。
   - `smartLive-api` 提供跨服务调用所需的接口与 DTO 定义。
5. **数据与中间件层**
   - MySQL、Redis、RabbitMQ、Elasticsearch、Milvus、MinIO、Nacos、Sentinel、Seata、XXL-JOB 等共同支撑核心链路。

## 7. 核心业务链路

### 7.1 用户消费链路

用户从首页推荐或搜索进入店铺，查看店铺和商品详情后完成下单、支付、履约和评价，后续还可以围绕订单内容继续进行博客发布、评论互动和社交传播。

### 7.2 商家经营链路

商家围绕店铺、商品、评价与订单做日常经营，平台通过热榜、经营指标、评价分析与 AI 文案能力辅助商家完成内容优化和服务改进。

### 7.3 平台治理链路

平台通过网关安全过滤、审核责任链、异步消息投递、搜索索引同步、向量库更新、定时任务对账等机制，保障系统在高并发和复杂业务下的稳定运行。

## 8. 关键技术方案

### 8.1 微服务拆分

项目按业务域进行高内聚拆分，把用户、店铺、商品、订单、互动、搜索、AI、审核等能力分离为独立服务，通过 Feign、MQ 和公共 API 模块协同。

### 8.2 Redis 分层缓存

项目对列表、详情、计数、热榜、Feed 等高频读场景进行分层缓存设计，使用 ZSet、String、计数器等不同结构分别承接不同访问模式，显著降低数据库压力。

### 8.3 高并发交易链路

在秒杀和高并发下单场景中，使用 Redis Lua 原子脚本处理库存预扣与一人一单校验，结合 RabbitMQ 延迟队列和死信队列处理超时取消与补偿回滚。

### 8.4 搜索与数据同步

项目采用 Elasticsearch 承接全文检索，业务数据通过消息队列异步同步到 ES；在 AI 相关场景中，再把店铺、商品、评价、博客等数据同步到 Milvus，支撑语义召回与 RAG 检索。

### 8.5 AI 与 RAG

AI 模块支持用户问答、商家经营分析、差评回复、博客生成、评价生成等场景，并通过多策略路由、会话记忆和向量检索提升回答质量与业务相关性。

### 8.6 调度与最终一致性

项目引入 XXL-JOB 承担热榜维护、库存校准、互动回刷、过期订单处理等任务，用于补足异步链路中的最终一致性与定时治理能力。
